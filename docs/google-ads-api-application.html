1. Business model

I manage digital marketing for a single advertiser: Juliana Capucci, a licensed clinical psychologist in Brazil (professional registration CRP 06/209216) who provides online psychotherapy sessions by video call.

The business is a solo clinical practice. Revenue comes directly from therapy sessions paid by the patient. There is no reselling of advertising services, no agency operation, and no third-party clients. I am the only person who will use the tool, and the only advertiser account involved is the practice's own account.

The practice's capacity is limited to roughly one to four new patients per month, so the advertising objective is not volume. It is to keep the cost per acquired patient within a known range and to stop spending when the schedule fills. That constraint is what drives the reporting need described below.

2. What the tool does

The tool is an internal, read-only reporting and analysis assistant. It runs on my own laptop and answers questions about the practice's own Google Ads account.

It is built from two off-the-shelf components:

  • Google Ads MCP Server — the official open-source server published by Google at github.com/googleads/google-ads-mcp, installed locally via pipx and run as a local stdio process. It is read-only by design and exposes three tools: search, get_resource_metadata and list_accessible_customers.
  • Claude Code — a command-line AI assistant that connects to the local MCP server and turns my questions into GAQL queries, then summarises the results.

I did not build a hosted product. There is no web application, no user accounts, no database of Google Ads data, and nothing exposed to the internet.

3. Why the API rather than the user interface

Three recurring reporting tasks are slow and error-prone in the interface and are the reason for this application:

  • Weekly search-terms review. Reading the search terms report and building the negative keyword list is the single most cost-saving routine early in a campaign. Querying it directly makes the review consistent instead of ad hoc.
  • Cost per acquired patient. Google Ads reports cost per conversion, but a conversion here is a WhatsApp click. The figure that matters is cost per patient who actually started therapy, which requires joining campaign cost data with an offline record I keep separately.
  • Campaign and keyword performance summaries across a small number of ad groups segmented by patient profile.

4. API services used

Service / methodPurpose
CustomerService.ListAccessibleCustomersIdentify which account to query
GoogleAdsService.Search (GAQL)Read campaign, ad group, keyword and search term metrics
GoogleAdsFieldService (resource metadata)Resolve available fields to build valid queries

No mutate operations are used. The tool cannot create, pause or modify campaigns, budgets, bids or assets. Every change to the account is made by hand in the Google Ads interface. This is a property of the official MCP server, which exposes no mutate methods at all.

Capability provided: Reporting only. The tool does not create or manage accounts or campaigns, and does not use keyword planning services.

Campaign types read: Search, and Display for the remarketing stage planned once the account has accumulated enough traffic.

Representative queries

SELECT search_term_view.search_term,
       metrics.clicks, metrics.impressions,
       metrics.cost_micros, metrics.conversions
FROM   search_term_view
WHERE  segments.date DURING LAST_7_DAYS

SELECT campaign.name, ad_group.name,
       metrics.cost_micros, metrics.conversions
FROM   keyword_view
WHERE  segments.date DURING LAST_30_DAYS

5. Data flow

  My terminal (local machine)
        |
        v
  Claude Code  --stdio-->  Google Ads MCP server (local process)
                                   |
                                   | HTTPS, OAuth 2.0 user credentials
                                   v
                         Google Ads API (read-only)

Results are returned to my terminal and summarised. Nothing is written to a server, nothing is cached beyond the lifetime of the session, and no Google Ads data leaves my machine other than back to Google. There is no data warehouse, no export pipeline, and no sharing with any third party.

6. Access and security

  • Users: internal only — one person, myself.
  • Accounts accessed: one advertiser account, belonging to the practice I manage, linked through my own manager account.
  • Authentication: OAuth 2.0 Application Default Credentials with the https://www.googleapis.com/auth/adwords scope, issued to an OAuth client in the Cloud project listed above.
  • Credential storage: credentials live only on my local machine, outside version control. The project's source repository is public, so the credentials directory is excluded by two independent gitignore layers, verified with git check-ignore.
  • Query volume: low — on the order of a few dozen queries per week, driven by a weekly review routine rather than by automated polling.

7. Interface

The tool has no graphical interface. Interaction happens in a terminal: I ask a question in plain language, the assistant issues one or more GAQL queries through the MCP server, and returns a table or short summary. A typical exchange looks like this:

> Which search terms spent money last week without producing a conversion?

  Running GAQL against search_term_view, last 7 days.

  Search term                      Clicks   Cost      Conversions
  psicologo online gratis              14   R$ 42,10            0
  curso de psicologia                   9   R$ 27,40            0

  Recommendation: add "gratis" and "curso" as negative keywords.
  (Applied manually in the Google Ads interface.)

8. Summary

A single practitioner's own advertising account, read by a single internal user, through Google's own open-source MCP server, with no mutate access, no hosted service, and no redistribution of data. The request is for Basic access so that production account data can be queried; a test-account token cannot serve this purpose.
